# System One Models 与 Jev：TypeSafe AI 的全新模型

**Diogo Almeida，TypeSafe 创始人**

大模型已经在聊天方面超越人类水平很多年了。

**那么，自动化到底在哪里？**

这是过去四年来一直驱动我的问题。

在 OpenAI 工作期间，我参与构建了让语言模型能够有效遵循指令、与人交流的方法。这项工作最终成为 ChatGPT 背后的研究基础。

当时，我曾认为聊天模型也许会引领我们走向 AGI。

但尽管外界充满了各种炒作，我逐渐意识到：**这里明显缺少了一些非常重要的东西。**

经过两年的隐身研发（stealth）、无数技术挑战以及一系列研究突破……

今天，我非常激动地宣布：

**TypeSafe AI 正式发布我们的第一个 System One Model——一种全新的前沿模型类别，专门用于快速、结构化地做出决策，并让软件能够直接使用这些决策。**

我们构建了一整套完全围绕自动化设计的新技术栈，包括：

- 全新的模型架构
- 用于最大化效率的并行采样器（parallel sampler）
- 一种我们称之为 **Reinforcement Learning for Calibrated Decisions（RLCD，校准决策强化学习）** 的训练方法

我们的第一个公开模型是 **Jev**，目前已经开启 Early Access。

在 System One 任务上，Jev 可以达到与现有 LLM 相近的智能水平，但速度和效率提升了**两个数量级**。

Jev 放弃了字符串生成能力，但针对结构化输出进行了优化，因此**不会产生幻觉（hallucination）**。

你可以把 Jev 理解成：

> **一个拥有前沿智能水平的函数调用：输入非结构化状态，输出带类型约束的概率决策。**

非凡的主张需要非凡的证据。

下面给出我们的数据和验证结果。

## 新旧两种 Frontiers

|          | 现有 LLM                                                                                                                                                                                                                 | System One + Jev                                                                                                                                                                                                                                                                                          |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **优化方式** | RLHF（基于人类反馈的强化学习） / RLVR（基于可验证奖励的强化学习）                                                                                                                                                                                 | RLCD（校准决策强化学习）                                                                                                                                                                                                                                                                                            |
| **优化目标** | 人类偏好：生成让人工评审更喜欢的文章和聊天回复。  <br>  <br>可验证奖励：生成能够通过程序验证的输出。                                                                                                                                                               | 校准后的决策：针对 System One 任务，输出具有认识论诚实性的概率。                                                                                                                                                                                                                                                                    |
| **输入**   | 非结构化数据，例如文本；强调连续的消息序列。                                                                                                                                                                                                 | 非结构化数据，例如文本；强调结构化的程序状态。                                                                                                                                                                                                                                                                                   |
| **输出**   | 字符串 / 生成文本。字符串非常灵活，可以表示任何东西：聊天回复、代码、幻觉、拒答，甚至类型安全的结构化值。  <br>  <br>如果软件需要使用这些回复，就必须进行解析和验证。同时，AI 始终存在“跑偏”的风险。                                                                                                           | 类型安全的结构化值。可能的输出以及结构都已经**预先定义**。模型不会产生类型错误。  <br>  <br>所有答案都会同时提供经过校准的概率和置信度分数。                                                                                                                                                                                                                            |
| **采样方式** | 顺序生成。一次生成一个 token，每个 token 都基于前一个 token。                                                                                                                                                                               | 并行生成。一次查询即可生成所有输出。效率极高，并且能够感知硬件特性。                                                                                                                                                                                                                                                                        |
| **成本**   | 输入 token：$0.20～$10 / MTok。  <br>  <br>输出 token：约为输入 token 成本的 5 倍。                                                                                                                                                     | 输入 token：$0.042 / MTok（每 10 亿 token 为 $42）。  <br>  <br>输出 token：**免费**（便宜到没有计量的意义）。                                                                                                                                                                                                                       |
| **速度**   | 前沿模型端到端响应时间约为 3～329 秒。  <br>  <br>对于与人交互来说足够快，但当模型集成进代码后，会成为一个巨大的瓶颈。                                                                                                                                                   | TypeSafe：端到端响应时间 70ms～500ms。  <br>  <br>对于相同水平的 System One 查询，可以实现约 **40～200 倍**的速度提升。                                                                                                                                                                                                                    |
| **置信度**  | 即使要求模型给出置信度，模型通常也会过度自信，而且表现不一致。  <br>  <br>如果一个模型完成某项任务的准确率是 95%，却无法告诉你什么时候属于剩下的 5%，那么它就无法可靠地自动化执行这项任务。                                                                                                                | 每一次输出都会明确表达置信度和不确定性。  <br>  <br>经过校准：置信度越高，准确率越高。  <br>  <br>更加一致：对于相似输入，会返回相似答案。                                                                                                                                                                                                                         |
| **使用场景** | 人在回路（Human-in-the-loop）任务：聊天机器人、Copilot、编程 Agent。  <br>  <br>通用且强大，但需要人工监督，因为模型拥有的自由度也意味着它可能跑偏。  <br>  <br>可验证问题：数学证明、内核优化等。当正确性可以低成本、自动验证时，LLM 可以生成、测试并迭代，直到找到可行方案。  <br>  <br>Demo：字符串的灵活性非常适合快速制作原型，即使这些原型有时才能正常工作。 | AI 驱动的工作流 / 智能 if 语句。  <br>  <br>结构化输出可以直接嵌入普通软件，成为一种模糊决策规则：分类、路由、评分、提取，或者在手写逻辑过于脆弱的地方进行分支。  <br>  <br>周围的代码限制了模型的自由度，因此更容易组合成可靠系统。  <br>  <br>大数据 Map-Reduce：将 PB 级数据转换成特征和洞察。  <br>  <br>实时应用：100ms 级速度意味着可以在对 UX 要求很高的应用中使用 AI。  <br>  <br>验证一切：评分、判断、验证、设置 Guardrail，以及检测 LLM Prompt、推理过程和/或输出中的越狱行为。 |
